# 個人記帳本資料表設計

資料庫：Supabase PostgreSQL。後端之後用 Flask 與 SQLAlchemy 讀寫。

## 0. 共通規則

### 0.1 規則標記

每一條規則後面都有一個標記：

- **〔DB〕**：用 PostgreSQL 的約束表達，例如 `NOT NULL`、`UNIQUE`、`CHECK`、`FOREIGN KEY`、identity、generated column、`DEFAULT`。
- **〔API〕**：由 API 在寫入前檢查。這類規則牽涉多列或跨表的累計，單一約束表達不了。

### 0.2 型別

| 用途 | 型別 | 說明 |
|---|---|---|
| 主鍵 | `bigint`，`GENERATED ALWAYS AS IDENTITY` | 由資料庫產生。〔DB〕identity 欄不接受插入時指定值，更新時也只能設成 `DEFAULT`，所以建立後不會被改。 |
| 金額 | `numeric(18,4)` | 可含小數。 |
| 股數 | `numeric(20,6)` | 可含小數，零股與海外碎股都能記。 |
| 匯率 | `numeric(18,8)` | 一單位外幣換成多少台幣。 |
| 幣別 | `char(3)` | 〔DB〕`CHECK` 必須是三碼大寫英文，例如 `TWD`、`USD`。 |
| 時間點 | `timestamptz` | `created_at`、`updated_at`、`prize_checked_at`。 |
| 日曆日 | `date` | 消費日、扣款日、入帳日、交易日、發票開立日。這些是「哪一天」，不是時間點。發票期別也要由日曆日算出，所以用 `date`。 |

### 0.3 每一張表都有的兩個欄位

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `created_at` | `timestamptz` | 必填 | 〔DB〕`NOT NULL DEFAULT now()`。插入時由資料庫填入。`timestamptz` 一律以 UTC 儲存。〔API〕插入時不送這個欄位，之後也不更新它。 |
| `updated_at` | `timestamptz` | 可空 | 插入時是空值。〔API〕每次 `UPDATE` 都由程式寫入當下的 UTC 時間。 |

下面各表的欄位清單不再重複這兩個欄位。

### 0.4 外鍵與刪除

- 〔DB〕所有外鍵都是 `ON DELETE RESTRICT`。父列還被參照時不能刪。
- 唯一例外：〔DB〕`invoice_items.invoice_id` 是 `ON DELETE CASCADE`，刪除發票時品項跟著一起消失。
- 主鍵不會改，所以外鍵不需要 `ON UPDATE` 連動。
- 這一次 API 不提供刪除帳務列的功能（見第 7 節）。不再使用的帳戶、分類、標的，用 `is_archived` 收起來。

### 0.5 外幣

- 每一筆帶金額的帳務列都有 `currency` 與 `fx_rate_to_twd`。
- 〔DB〕`CHECK (fx_rate_to_twd > 0)`。
- 〔DB〕`CHECK (currency <> 'TWD' OR fx_rate_to_twd = 1)`，台幣的匯率是 1。
- 〔DB〕帳務列的幣別必須等於所屬帳戶的幣別。做法：`accounts` 加 `UNIQUE (id, currency)`，帳務列用複合外鍵 `(account_id, currency)` 指向 `accounts (id, currency)`。這樣同一個帳戶的金額可以直接加減，不必先換匯。

## 1. 帳戶

### 1.1 `accounts` 帳戶

**記什麼**：錢放在哪裡，包含現金、銀行、信用卡、券商交割戶。
**為什麼單獨成表**：入帳、花費、移轉、投資交易都要指向「錢落在哪個帳戶」。帳戶的名稱與幣別只記一次，各冊子共用。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `name` | `text` | 必填 | 〔DB〕`UNIQUE`。〔DB〕`CHECK` 去掉前後空白後不是空字串。 |
| `account_type` | `text` | 必填 | 〔DB〕`CHECK` 值只能是 `cash`、`bank`、`credit_card`、`brokerage`。 |
| `currency` | `char(3)` | 必填 | 這個帳戶的幣別。〔DB〕三碼大寫。 |
| `opening_amount` | `numeric(18,4)` | 必填 | 開始記帳時的期初金額，〔DB〕`DEFAULT 0`。這是起算點，不是餘額，見第 6 節。信用卡欠款記成負數。 |
| `opened_on` | `date` | 可空 | 期初金額是哪一天的金額。 |
| `is_archived` | `boolean` | 必填 | 〔DB〕`DEFAULT false`。 |
| `note` | `text` | 可空 | |

其他約束：

- 〔DB〕`UNIQUE (id, currency)`，給第 0.5 節的複合外鍵使用。
- 〔DB〕帳戶被帳務列參照後，複合外鍵會擋下修改 `currency`。
- 〔API〕帳戶已經有帳務列之後，不允許修改 `opening_amount` 與 `opened_on`。要改期初金額時，先確認沒有任何帳務列。

## 2. 分類

入帳與花費的分類分開成兩張表，名稱在各自的表內不能重複。同一個名字可以同時出現在兩張表，例如兩邊都有「其他」。

### 2.1 `income_categories` 入帳分類

**記什麼**：入帳的分類，例如薪水、獎金、利息、退款、股利、發票中獎。
**為什麼單獨成表**：分類名稱只存一次，改名時不必改每一筆入帳。分類與花費分類分開，選單不會混在一起，名稱也各自唯一。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `name` | `text` | 必填 | 〔DB〕`UNIQUE`。〔DB〕`CHECK` 去掉前後空白後不是空字串。 |
| `is_archived` | `boolean` | 必填 | 〔DB〕`DEFAULT false`。 |

### 2.2 `expense_categories` 花費分類

**記什麼**：花費的分類，例如餐飲、交通、房租、手續費。
**為什麼單獨成表**：理由同 2.1。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `name` | `text` | 必填 | 〔DB〕`UNIQUE`。〔DB〕`CHECK` 去掉前後空白後不是空字串。 |
| `is_archived` | `boolean` | 必填 | 〔DB〕`DEFAULT false`。 |

## 3. 入帳、花費、移轉

### 3.1 `incomes` 入帳

**記什麼**：錢進到一個帳戶，例如薪水、獎金、利息、退款、發票中獎獎金、現金股利、減資退回的現金。
**為什麼單獨成表**：入帳是四本冊子之一，欄位跟花費不同：入帳可以連到一張中獎發票或一筆投資交易，花費則有扣款日並可連到發票。分開成表，兩邊的約束都比較單純。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `account_id` | `bigint` | 必填 | 外鍵 → `accounts.id`。錢進到哪個帳戶。 |
| `category_id` | `bigint` | 必填 | 外鍵 → `income_categories.id`。 |
| `received_on` | `date` | 必填 | 入帳日。 |
| `amount` | `numeric(18,4)` | 必填 | 帳戶幣別的金額。〔DB〕`CHECK (amount > 0)`。 |
| `currency` | `char(3)` | 必填 | 〔DB〕複合外鍵 `(account_id, currency)` → `accounts (id, currency)`。 |
| `fx_rate_to_twd` | `numeric(18,8)` | 必填 | 見第 0.5 節。 |
| `description` | `text` | 可空 | |
| `invoice_id` | `bigint` | 可空 | 外鍵 → `invoices.id`。這筆是哪一張發票的中獎獎金。〔DB〕`UNIQUE`，一張發票最多一筆入帳。 |
| `investment_trade_id` | `bigint` | 可空 | 外鍵 → `investment_trades.id`。這筆是哪一筆現金股利或減資的現金。〔DB〕`UNIQUE`，一筆交易最多一筆入帳。 |
| `note` | `text` | 可空 | |

其他約束：

- 〔DB〕`CHECK (num_nonnulls(invoice_id, investment_trade_id) <= 1)`，一筆入帳不能同時是發票獎金與投資現金。
- 〔API〕`invoice_id` 有值時，該發票的 `won_prize_id` 必須有值，也就是已經確認中獎。
- 〔API〕`investment_trade_id` 有值時，該交易的 `trade_type` 必須是 `cash_dividend` 或 `capital_reduction`。若是 `capital_reduction`，該交易的 `amount` 必須大於 0。
- 〔API〕`investment_trade_id` 有值時，入帳的 `currency` 必須等於該交易的 `currency`。

### 3.2 `expenses` 花費

**記什麼**：錢從一個帳戶出去。消費日與扣款日分開記，例如信用卡在 3 月 28 日刷卡、4 月 15 日扣款。
**為什麼單獨成表**：花費是四本冊子之一，有自己的分類、扣款日，也可以對到發票。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `account_id` | `bigint` | 必填 | 外鍵 → `accounts.id`。錢從哪個帳戶出去。 |
| `category_id` | `bigint` | 必填 | 外鍵 → `expense_categories.id`。 |
| `spent_on` | `date` | 必填 | 消費日。 |
| `posted_on` | `date` | 可空 | 扣款日。空值表示與消費日同一天。 |
| `amount` | `numeric(18,4)` | 必填 | 帳戶幣別的金額。〔DB〕`CHECK (amount > 0)`。 |
| `currency` | `char(3)` | 必填 | 〔DB〕複合外鍵 `(account_id, currency)` → `accounts (id, currency)`。 |
| `fx_rate_to_twd` | `numeric(18,8)` | 必填 | 見第 0.5 節。 |
| `description` | `text` | 可空 | 店家或用途。 |
| `invoice_id` | `bigint` | 可空 | 外鍵 → `invoices.id`。可以有多筆花費指向同一張發票。 |
| `note` | `text` | 可空 | |

其他約束：

- 〔API〕`posted_on` 只有在帳戶的 `account_type` 是 `credit_card` 時才可以填。
- 不檢查「指向同一張發票的花費合計等於發票總額」，兩者不必相等。
- 退款不寫成負的花費，要記成一筆入帳（`amount > 0` 已經擋下負數）。

### 3.3 `transfers` 移轉

**記什麼**：錢從一個帳戶到另一個帳戶，例如提款、繳信用卡費、匯款到交割戶、換匯。
**為什麼單獨成表**：移轉不是入帳，也不是花費。如果拆成一筆花費加一筆入帳，收支報表會多算。移轉同時改變兩個帳戶，所以一列要有兩邊的帳戶與金額。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `transferred_on` | `date` | 必填 | 移轉日。 |
| `from_account_id` | `bigint` | 必填 | 外鍵 → `accounts.id`。轉出帳戶。 |
| `from_amount` | `numeric(18,4)` | 必填 | 轉出帳戶減少的金額。〔DB〕`CHECK (from_amount > 0)`。 |
| `from_currency` | `char(3)` | 必填 | 〔DB〕複合外鍵 `(from_account_id, from_currency)` → `accounts (id, currency)`。 |
| `from_fx_rate_to_twd` | `numeric(18,8)` | 必填 | 〔DB〕`> 0`；`from_currency` 是 `TWD` 時必須是 1。 |
| `to_account_id` | `bigint` | 必填 | 外鍵 → `accounts.id`。轉入帳戶。 |
| `to_amount` | `numeric(18,4)` | 必填 | 轉入帳戶增加的金額。〔DB〕`CHECK (to_amount > 0)`。 |
| `to_currency` | `char(3)` | 必填 | 〔DB〕複合外鍵 `(to_account_id, to_currency)` → `accounts (id, currency)`。 |
| `to_fx_rate_to_twd` | `numeric(18,8)` | 必填 | 〔DB〕`> 0`；`to_currency` 是 `TWD` 時必須是 1。 |
| `note` | `text` | 可空 | |

其他約束：

- 〔DB〕`CHECK (from_account_id <> to_account_id)`。
- 〔DB〕`CHECK (from_currency <> to_currency OR from_amount = to_amount)`，同幣別的移轉兩邊金額相等。
- 轉帳手續費另記一筆花費，不放在移轉列裡。

## 4. 投資

### 4.1 `securities` 投資標的

**記什麼**：一檔標的，例如一檔股票或 ETF。
**為什麼單獨成表**：同一檔標的會有很多筆交易。代號、名稱、幣別只記一次。持有股數與平均成本都以標的為單位計算。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `market` | `text` | 必填 | 市場代碼，例如 `TWSE`、`TPEx`、`NASDAQ`。 |
| `symbol` | `text` | 必填 | 代號，例如 `2330`、`0050`。 |
| `name` | `text` | 必填 | |
| `currency` | `char(3)` | 必填 | 交易幣別。〔DB〕三碼大寫。 |
| `is_archived` | `boolean` | 必填 | 〔DB〕`DEFAULT false`。 |
| `note` | `text` | 可空 | |

其他約束：

- 〔DB〕`UNIQUE (market, symbol)`。
- 〔DB〕`UNIQUE (id, currency)`，給交易的複合外鍵使用。

### 4.2 `investment_trades` 投資交易

**記什麼**：一檔標的的每一筆股數或成本異動。
**為什麼單獨成表**：持有股數與平均成本都由交易依序算出，所以每一筆異動都要留下來。交易有股數、手續費、稅、交割帳戶，跟入帳與花費的欄位不同。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `security_id` | `bigint` | 必填 | 外鍵 → `securities.id`。 |
| `trade_type` | `text` | 必填 | 〔DB〕`CHECK` 值只能是下表八種之一。 |
| `traded_on` | `date` | 必填 | 交易日或除權息生效日。 |
| `quantity_delta` | `numeric(20,6)` | 必填 | 持有股數的增減，有正負號。正負規則見下表。 |
| `unit_price` | `numeric(18,6)` | 可空 | 成交單價，只供參考，算成本時以 `amount` 為準。 |
| `amount` | `numeric(18,4)` | 必填 | 金額，意義依種類而定，見下表。〔DB〕`CHECK (amount >= 0)`。 |
| `fee` | `numeric(18,4)` | 必填 | 手續費。〔DB〕`DEFAULT 0`，`CHECK (fee >= 0)`。 |
| `tax` | `numeric(18,4)` | 必填 | 交易稅。〔DB〕`DEFAULT 0`，`CHECK (tax >= 0)`。 |
| `currency` | `char(3)` | 必填 | 〔DB〕複合外鍵 `(security_id, currency)` → `securities (id, currency)`，必須等於標的幣別。 |
| `fx_rate_to_twd` | `numeric(18,8)` | 必填 | 見第 0.5 節。 |
| `settlement_account_id` | `bigint` | 可空 | 外鍵 → `accounts.id`。買進、賣出時錢從哪個交割戶進出。〔DB〕複合外鍵 `(settlement_account_id, currency)` → `accounts (id, currency)`；欄位是空值時這個外鍵不檢查。 |
| `note` | `text` | 可空 | |

各種類的規則，全部是〔DB〕`CHECK`，依 `trade_type` 分別判斷：

| `trade_type` | 中文 | `quantity_delta` | `amount` 的意義 | `unit_price` | `settlement_account_id` | `fee`、`tax` |
|---|---|---|---|---|---|---|
| `buy` | 買進 | `> 0` | 成交金額，`> 0` | 必填，`> 0` | 必填 | 可大於 0 |
| `sell` | 賣出 | `< 0` | 成交金額，`> 0` | 必填，`> 0` | 必填 | 可大於 0 |
| `cash_dividend` | 現金股利 | `= 0` | 股利總額，`> 0` | 空值 | 空值 | 都是 0 |
| `stock_dividend` | 配股 | `> 0` | `= 0` | 空值 | 空值 | 都是 0 |
| `dividend_reinvest` | 股息再投入 | `> 0` | 再投入的金額，`> 0` | 可空 | 空值 | `fee` 可大於 0，`tax` 是 0 |
| `split` | 分割 | `> 0`（分割後增加的股數） | `= 0` | 空值 | 空值 | 都是 0 |
| `reverse_split` | 合併 | `< 0`（合併後減少的股數） | `= 0` | 空值 | 空值 | 都是 0 |
| `capital_reduction` | 減資 | `<= 0`（銷除的股數） | 退回的現金，`>= 0` | 空值 | 空值 | 都是 0 |

- 〔DB〕`capital_reduction` 另外要求 `quantity_delta < 0 OR amount > 0`，不能兩者都是 0。
- 現金股利與減資退回的現金，實際進帳戶的那筆錢記在 `incomes`，用 `incomes.investment_trade_id` 指回這筆交易。所以這兩種交易的 `settlement_account_id` 是空值，避免重複計入帳戶餘額。入帳金額可以小於 `amount`，例如扣掉匯費或補充保費。
- 股息再投入的現金沒有進到任何帳戶，直接換成股數，所以不另記入帳。

**持有不得小於 0**：〔API〕寫入 `sell`、`reverse_split`、`capital_reduction`，或修改任何一筆交易的 `traded_on`、`quantity_delta` 前，API 先鎖住該標的，再把該標的所有交易依 `(traded_on, id)` 排序，逐筆累加 `quantity_delta`。每一步的累計值都必須 `>= 0`。補登一筆較早日期的賣出時，之後每一步也要重算。這是跨多列的累計，單一約束表達不了，所以由 API 檢查。

## 5. 發票

### 5.1 統一發票期別

統一發票每兩個月一期：1–2 月、3–4 月、5–6 月、7–8 月、9–10 月、11–12 月。

期別存成六位整數 `YYYYMM`：`YYYY` 是開立日的西元年，`MM` 是該期的第一個月，一定是 1、3、5、7、9、11。

由開立日決定期別：

- 設開立日的西元年為 *y*，月份為 *m*（1–12）。
- 起始月 = *m* 是奇數時為 *m*，是偶數時為 *m* − 1。
- 期別 = *y* × 100 + 起始月。

例子：2026-04-30 開立 → 202603（2026 年 3–4 月期，也就是民國 115 年 03–04 月期）。2026-11-01 開立 → 202611。

民國年的顯示由 API 換算（西元年 − 1911），資料庫只存西元。

### 5.2 `invoices` 發票

**記什麼**：一張台灣統一發票的表頭，用來留底與對獎。
**為什麼單獨成表**：一張發票有多個品項，也可以對到多筆花費，所以發票要自己一列，品項與花費才能指向它。對獎結果也以一張發票為單位。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `invoice_number` | `char(10)` | 必填 | 〔DB〕`UNIQUE`，全庫不重複。〔DB〕`CHECK` 必須是兩碼大寫英文加八碼數字，例如 `AB12345678`。 |
| `issued_on` | `date` | 必填 | 開立日。 |
| `period` | `integer` | 必填 | 〔DB〕generated column（`STORED`），依第 5.1 節由 `issued_on` 算出，程式不能寫入。 |
| `seller_name` | `text` | 可空 | |
| `seller_tax_id` | `char(8)` | 可空 | 賣方統一編號。〔DB〕`CHECK` 必須是八碼數字。 |
| `random_code` | `char(4)` | 可空 | 隨機碼。〔DB〕`CHECK` 必須是四碼數字。 |
| `total_amount` | `numeric(18,4)` | 必填 | 發票總額，新台幣。〔DB〕`CHECK (total_amount >= 0)`。 |
| `won_prize_id` | `bigint` | 可空 | 外鍵 → `invoice_draw_prizes.id`。對獎後中了哪一個獎；空值表示沒中或還沒對。 |
| `prize_checked_at` | `timestamptz` | 可空 | 對獎完成的時間；空值表示還沒對。 |
| `note` | `text` | 可空 | |

其他約束：

- 〔DB〕`invoice_number` 全庫 `UNIQUE`，不只是同一期內不重複。同一個號碼不能記成兩張發票，也就不會重複對獎或重複記中獎入帳。
- 〔DB〕`CHECK (won_prize_id IS NULL OR prize_checked_at IS NOT NULL)`，有中獎就一定有對獎時間。
- 〔API〕`won_prize_id` 指向的獎項，所屬開獎期別必須等於這張發票的 `period`。
- 〔API〕一張發票只對到一個獎：同時符合多個獎時，取 `prize_amount` 最高的那一個。
- 統一發票一律是新台幣，所以這張表沒有 `currency` 與 `fx_rate_to_twd`。

### 5.3 `invoice_items` 發票品項

**記什麼**：一張發票上的每一個品項。
**為什麼單獨成表**：一張發票有多個品項，數量不固定。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `invoice_id` | `bigint` | 必填 | 外鍵 → `invoices.id`，〔DB〕`ON DELETE CASCADE`。這是全部設計中唯一的連動刪除。 |
| `line_no` | `integer` | 必填 | 品項在發票上的順序。〔DB〕`CHECK (line_no > 0)`。 |
| `item_name` | `text` | 必填 | |
| `quantity` | `numeric(18,4)` | 必填 | 〔DB〕`DEFAULT 1`，`CHECK (quantity > 0)`。 |
| `unit_price` | `numeric(18,4)` | 可空 | |
| `amount` | `numeric(18,4)` | 必填 | 這一行的小計，新台幣。可以是負數，表示折扣。 |

其他約束：

- 〔DB〕`UNIQUE (invoice_id, line_no)`。
- 不檢查品項小計合計等於發票總額。

### 5.4 `invoice_draws` 開獎期別

**記什麼**：每一期統一發票的開獎。
**為什麼單獨成表**：中獎號碼與獎金都屬於某一期。先有一列代表這一期，號碼與獎金再指向它。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `period` | `integer` | 必填 | 格式同第 5.1 節。〔DB〕`UNIQUE`。〔DB〕`CHECK` 月份部分（`period` 除以 100 的餘數）是 1、3、5、7、9、11 之一。 |
| `drawn_on` | `date` | 可空 | 開獎日。 |
| `note` | `text` | 可空 | |

### 5.5 `invoice_winning_numbers` 中獎號碼

**記什麼**：某一期公告的中獎號碼。
**為什麼單獨成表**：每一期的號碼數量不固定，例如頭獎有三組，增開六獎可能有零到多組。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `draw_id` | `bigint` | 必填 | 外鍵 → `invoice_draws.id`。 |
| `number_kind` | `text` | 必填 | 〔DB〕`CHECK` 值只能是 `special`（特別獎）、`grand`（特獎）、`first`（頭獎）、`additional_sixth`（增開六獎）。 |
| `winning_number` | `text` | 必填 | 〔DB〕`CHECK`：`additional_sixth` 必須是三碼數字，其他三種必須是八碼數字。 |

其他約束：

- 〔DB〕`UNIQUE (draw_id, number_kind, winning_number)`。
- 〔API〕每一期 `special` 與 `grand` 各最多一組。

### 5.6 `invoice_draw_prizes` 開獎獎金

**記什麼**：某一期每一個獎別的獎金，以及怎麼比對號碼。
**為什麼單獨成表**：獎金與比對規則放在資料表，不寫死在程式裡。獎金如果調整，新一期寫入新的數字，舊期別的紀錄不受影響。

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---|---|
| `id` | `bigint` identity | 必填 | 主鍵。 |
| `draw_id` | `bigint` | 必填 | 外鍵 → `invoice_draws.id`。 |
| `tier` | `text` | 必填 | 獎別代碼，例如 `special`、`grand`、`first`、`second`、`third`、`fourth`、`fifth`、`sixth`、`additional_sixth`。 |
| `tier_name` | `text` | 必填 | 顯示名稱，例如「二獎」。 |
| `match_number_kind` | `text` | 必填 | 跟哪一種中獎號碼比對。〔DB〕`CHECK` 值與 `invoice_winning_numbers.number_kind` 相同的四種。 |
| `match_last_digits` | `integer` | 必填 | 比對末幾碼。〔DB〕`CHECK (match_last_digits BETWEEN 3 AND 8)`。 |
| `prize_amount` | `numeric(18,4)` | 必填 | 獎金，新台幣。〔DB〕`CHECK (prize_amount > 0)`。 |

其他約束：

- 〔DB〕`UNIQUE (draw_id, tier)`。

**對獎方式**：〔API〕取發票號碼的八碼數字（不比對字軌英文），對這張發票 `period` 那一期的每一個獎別：找出 `match_number_kind` 相同的中獎號碼，比對末 `match_last_digits` 碼，相同就符合。符合多個獎別時取 `prize_amount` 最高的，寫入 `invoices.won_prize_id`，並寫入 `prize_checked_at`。

以下是一期資料可能的樣子。數字是資料列，不是程式常數，實際以當期公告為準：

| `tier` | `tier_name` | `match_number_kind` | `match_last_digits` | `prize_amount` |
|---|---|---|---|---|
| `special` | 特別獎 | `special` | 8 | 10000000 |
| `grand` | 特獎 | `grand` | 8 | 2000000 |
| `first` | 頭獎 | `first` | 8 | 200000 |
| `second` | 二獎 | `first` | 7 | 40000 |
| `third` | 三獎 | `first` | 6 | 10000 |
| `fourth` | 四獎 | `first` | 5 | 4000 |
| `fifth` | 五獎 | `first` | 4 | 1000 |
| `sixth` | 六獎 | `first` | 3 | 200 |

## 6. 算出來的值：餘額、持有股數、平均成本

這三個值都不存成欄位，每次查詢時由下面的列算出。資料庫裡沒有可以直接修改它們的地方。

### 6.1 帳戶餘額

帳戶 A 在日期 D 的餘額，以帳戶 A 的幣別計算：

| 加減 | 來源 | 條件 |
|---|---|---|
| ＋ | `accounts.opening_amount` | 帳戶 A |
| ＋ | `incomes.amount` | `account_id = A` 且 `received_on <= D` |
| − | `expenses.amount` | `account_id = A` 且「`posted_on`，若為空值則用 `spent_on`」`<= D` |
| ＋ | `transfers.to_amount` | `to_account_id = A` 且 `transferred_on <= D` |
| − | `transfers.from_amount` | `from_account_id = A` 且 `transferred_on <= D` |
| − | `investment_trades.amount + fee + tax` | `trade_type = 'buy'`、`settlement_account_id = A`、`traded_on <= D` |
| ＋ | `investment_trades.amount − fee − tax` | `trade_type = 'sell'`、`settlement_account_id = A`、`traded_on <= D` |

- 花費以扣款日計入餘額，所以信用卡在扣款日才減少。
- 現金股利與減資退回的現金只透過 `incomes` 計入，不透過 `investment_trades`。
- 同一帳戶的列幣別都相同（第 0.5 節的複合外鍵保證），可以直接加總。要換成台幣時，每一列各自乘上自己的 `fx_rate_to_twd`。

### 6.2 持有股數

標的 S 在日期 D 的持有股數 = 該標的所有 `traded_on <= D` 的 `investment_trades.quantity_delta` 總和。

### 6.3 平均成本

把標的 S 的交易依 `(traded_on, id)` 排序，從「持有 0 股、總成本 0」開始逐筆計算：

| `trade_type` | 持有股數 | 總成本 |
|---|---|---|
| `buy` | 加 `quantity_delta` | 加 `amount + fee + tax` |
| `dividend_reinvest` | 加 `quantity_delta` | 加 `amount + fee` |
| `sell` | 加 `quantity_delta`（負數） | 依賣出比例減少：總成本 × 賣出股數 ÷ 賣出前股數 |
| `cash_dividend` | 不變 | 不變 |
| `stock_dividend` | 加 `quantity_delta` | 不變 |
| `split`、`reverse_split` | 加 `quantity_delta` | 不變 |
| `capital_reduction` | 加 `quantity_delta`（零或負數） | 減 `amount`，最低為 0 |

平均成本 = 總成本 ÷ 持有股數，持有股數大於 0 時才有值。持有歸 0 時總成本也歸 0。
